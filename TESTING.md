# Testing the v0.2.0 preview

[Download Orbit for Windows x64](https://github.com/luckypolamreddy/orbit-downloads/releases/download/v0.2.0/Orbit-0.2.0-win-x64.exe) · [All installers](README.md) · [SHA256SUMS.txt](https://github.com/luckypolamreddy/orbit-downloads/releases/download/v0.2.0/SHA256SUMS.txt)

Use this unsigned, non-notarized development preview only for controlled testing. Security review and real-device coverage remain pending. Record the Orbit version, OS, processor, display setup and the result of each check. Package availability does not establish that capture or native control has been validated on that platform.

1. **Install and verify.** Choose the package for your OS and processor. Compare its SHA-256 hash with the matching entry in `SHA256SUMS.txt`. Launch Orbit and confirm the app opens and Settings are available. Respect operating-system trust and permission prompts.
2. **Check server setup.** Configure the same supplied Orbit server URL on all clients. The backend is not bundled. The current local service on port 8787 supports only the same computer. Two-laptop testing requires a reachable `wss://` server; a shared public server has not yet been deployed. Record this test as blocked until one is available.
3. **Admission and devices.** Create a room, join its code from a second client and check that admission is required. Confirm microphone and camera start off. Enable each explicitly, check the intended device, then stop it. Exercise denied permissions and missing or disconnected devices; the app should explain unavailable features without starting capture unexpectedly.
4. **Sharing and control.** Use non-sensitive sample content. Select the primary entire monitor and confirm the owner can see sharing status and Stop controls. Request control from the other client; verify it requires the owner's separate approval. Confirm denial prevents input, approval permits supported input, and revoking control or stopping sharing prevents further input immediately. Window shares should remain view-only. Test leaving and disconnecting too. Each control grant lasts up to 10 minutes. macOS permissions and Linux X11/optional-driver availability can limit control.
5. **One-hour expiry.** Leave a controlled room running until its fixed deadline, measured from room creation. Reapprove control shortly before the deadline so a live control grant is present for this check. Confirm capture and control stop for all participants and reconnecting does not extend the deadline. Start a fresh room and confirm it uses a new code. Separately check that admission codes expire after 15 minutes and the host can rotate an invitation without extending the one-hour room deadline.
6. **Private text and dictation.** With three admitted clients, send sample private text to one chosen recipient and check that the third client does not receive it. If supported, explicitly start dictation using only your own test speech, preferably through a headset. Confirm the call microphone stays muted, final recognized text reaches the chosen recipient and Stop ends recognition. Check typing when recognition is unavailable. Do not capture or relay audio from an external meeting.
7. **Presentation mode and cleanup.** Before any entire-display share in Teams, manually enable Presentation mode and confirm private text, drafts and previews disappear from your own Orbit screen. Stop the external share before turning the mode off. Leave the Orbit room and confirm media/control stop, private messages clear and no recent-meeting history appears after reopening.

Report failures with reproducible steps and the relevant platform details. Remove room codes, server credentials and private content from screenshots or logs before sharing a report.
